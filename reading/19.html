实践经验2026-09-03 17:43值得读

不同模型与工具的速度、体感和任务分配经验

群友报告 GPT 当时响应很慢；另有人称公司使用的 GLM 5.3 Flash 也偏慢。对 Gemini 3.8 Flash，有人称刚实测响应很快，也有人觉得能力差或体验不稳；这些评价针对当时的使用场景，不能据此推断普遍表现。群友还比较了 Codex、不同模型档位、豆包和其他办公工具：有人倾向用能力较强的模型做顶层设计、较低成本的工具执行，也有人表示文件类工作可直接上传豆包并用自然语言指挥，持续工作则偏向本地处理。讨论者特别指出，MCP 和 Skills 等工具能力并不完全由模型档位决定。

包含短任务与文件工作中的工具分配思路，以及模型速度和体感评价的分歧，适合形成自己的任务基准。

挑选常见任务做并行小样测试，分别记录响应时间、返工量、输出质量和调用成本。

观点方法2026-09-03 16:55值得读

用上下文依赖与交接量判断何时拆分子 Agent

群友围绕 Codex 子 Agent 讨论：一位参与者说明，父 Agent 会将任务摘要发给子 Agent，子 Agent 不会自动读取父对话历史；上下文具体占用和 token 节省没有得到核实。另有两种拆分建议：耗时较长、适合后台独立处理的任务可交给子 Agent；更一般地，可以按上下文切割，优先拆出与主任务共享信息少、结果回传量小的独立任务。有人建议复杂交叉任务使用多个专家并互评，但也提醒这会增加 token 成本。

提供了可实践的子 Agent 拆分标准，并保留多专家并行方法及其成本顾虑。

从一个上下文依赖少、交付结果明确的 Codex 子任务开始试拆，并观察摘要与结果交接是否足够。
